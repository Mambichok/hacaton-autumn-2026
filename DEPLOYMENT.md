# Закрытый тестовый VPS

Эта конфигурация предназначена только для закрытого пилота с вымышленными документами. Она не является подтверждением готовности к обработке реальных банковских или персональных данных.

## Что будет опубликовано

- FastAPI запускается в контейнере от непривилегированного пользователя.
- Приложение доступно на VPS только через `127.0.0.1:8766`; Nginx публикует его на `8080` только для подсети WireGuard `10.77.0.0/24`.
- Qdrant не публикует порт на хост и доступен только контейнеру приложения.
- База администраторов, загруженные документы и данные Qdrant хранятся в именованных Docker volumes.
- Загруженные администратором DOCX-шаблоны и их поля также хранятся в `app_data`; сотрудник скачивает только заполненный DOCX.
- Внешний AI используется только для синтетических данных в закрытом тесте.

## Перед запуском

1. Убедитесь, что у вас есть доступ к консоли VPS и сохранённый способ восстановить SSH-доступ. Не включайте firewall, пока не разрешили используемый SSH-порт.
2. Установите Docker Engine с Compose plugin, Nginx, WireGuard и UFW для Ubuntu. Для Docker используйте официальную инструкцию установки для Ubuntu.
3. Не копируйте на VPS настоящий `.env`, локальную базу администраторов, загруженные документы или Qdrant storage.
4. Не размещайте в `deploy/source-documents` документы банка и реальные персональные данные. Каталог исключён из Docker image; заполняйте его на VPS только утверждёнными синтетическими DOCX/PDF-файлами.
5. Уточните с организацией допустимость использования внешнего AI-провайдера даже для выбранных тестовых материалов.

При первом запуске приложение добавляет в каталог 10 универсальных DOCX-шаблонов: кадровые заявления, формы для финансов и заявки на ИТ-доступ. Они создаются приложением и не являются утвержденными внутренними формами Банка. Перед использованием согласуйте их с кадровой, финансовой, юридической и информационно-безопасностной службами. Шаблон налогового вычета не фиксирует суммы; проверьте право на вычет и комплект документов по актуальной редакции законодательства.

Кадровые и налоговые формулировки — редактируемые типовые заготовки, а не копии утвержденных бланков. Проверяйте их по действующим редакциям [Трудового кодекса РФ](https://www.consultant.ru/document/cons_doc_LAW_34683/) и [Налогового кодекса РФ](https://www.consultant.ru/document/cons_doc_LAW_28165/), а также по локальным правилам организации.

Чтобы добавить свой шаблон, администратор загружает DOCX, выделяет в текстовом предпросмотре фрагменты для заполнения и задает подпись и тип каждого поля (текст или дата). Система сама размещает поля в DOCX; вручную добавлять метки `{{field_name}}` не требуется. Сотрудники находят шаблоны через каталог с категориями и поиском, а скачивают заполненный документ в DOCX.

## Настройка WireGuard

Выбран закрытый адресный диапазон `10.77.0.0/24`. Приложение будет открываться внутри VPN по `http://10.77.0.1:8080`.

Создайте ключи сервера на VPS и клиента на клиентском устройстве. Никогда не пересылайте приватные ключи в чат и не сохраняйте их в репозитории:

```sh
umask 077
wg genkey | tee server.key | wg pubkey > server.pub
```

На клиенте создайте отдельную пару ключей WireGuard. Передайте на сервер только публичный ключ клиента. Создайте `/etc/wireguard/wg0.conf` с правами `600`:

```ini
[Interface]
Address = 10.77.0.1/24
ListenPort = 51820
PrivateKey = <server-private-key>

[Peer]
PublicKey = <client-public-key>
AllowedIPs = 10.77.0.2/32
```

Создайте клиентский профиль на своём устройстве:

```ini
[Interface]
Address = 10.77.0.2/32
PrivateKey = <client-private-key>

[Peer]
PublicKey = <server-public-key>
Endpoint = 84.21.191.28:51820
AllowedIPs = 10.77.0.0/24
PersistentKeepalive = 25
```

Не включайте `0.0.0.0/0`: весь интернет-трафик через тестовый VPS не требуется.

Запустите WireGuard и проверьте handshake, прежде чем закрывать SSH:

```sh
systemctl enable --now wg-quick@wg0
wg show
```

Если SSH работает на стандартном порту и UFW ещё не настроен, добавьте правила, сохраняя разрешение для SSH. Для нестандартного SSH-порта добавьте именно его:

```sh
ufw allow OpenSSH
ufw allow 51820/udp
ufw insert 1 allow in on wg0 from 10.77.0.0/24 to any port 8080 proto tcp
ufw deny 8080/tcp
ufw default deny incoming
ufw default allow outgoing
ufw status numbered
```

Проверьте правила и доступ через вторую SSH-сессию, затем включайте UFW командой `ufw enable`. Не выполняйте её, пока не убедились, что SSH разрешён. Конфигурация Nginx дополнительно запрещает доступ вне VPN-подсети.

Доступ к приложению идёт по HTTP внутри WireGuard-туннеля; сам туннель шифрует трафик. Не открывайте `8080`, `8766`, `6333` или `6334` напрямую в интернет. Nginx проверяет VPN-адрес клиента, а Docker публикует порт приложения только на loopback.

## Развёртывание приложения

Скопируйте исходный код без `.env` и документов в `/opt/document-assistant`. В каталоге проекта на VPS:

```sh
mkdir -p deploy/source-documents
cp deploy/vps.env.example deploy/vps.env
chmod 600 deploy/vps.env
```

Отредактируйте `deploy/vps.env` на VPS. Задайте супер-администратору уникальный пароль длиной не менее 14 символов, `ADMIN_SESSION_SECRET` из результата `python3 -c "import secrets; print(secrets.token_urlsafe(48))"` и актуальный AI API key. Не вставляйте значения секретов в команды, которые сохраняют shell history, и не отправляйте их в чат.

Положите только вымышленные тестовые документы в `deploy/source-documents`, затем установите конфигурацию Nginx:

```sh
cp deploy/nginx-site.conf /etc/nginx/sites-available/document-assistant
ln -s /etc/nginx/sites-available/document-assistant /etc/nginx/sites-enabled/document-assistant
nginx -t
systemctl reload nginx
```

Если у Nginx уже есть default site на этом же порту, сначала отключите конфликтующий конфиг. Убедитесь, что UFW разрешает порт `8080` только на `wg0`.

Соберите и запустите сервисы:

```sh
docker compose build --pull
docker compose up -d
docker compose ps
```

Дождитесь готовности Qdrant, проверив состояние сервиса и его логи:

```sh
docker compose logs --tail=50 qdrant
```

Проверьте, что Qdrant не опубликован на host:

```sh
docker compose port qdrant 6333
```

Команда не должна показать внешний host port. Индексация создаёт новую коллекцию,
проверяет число загруженных фрагментов и только после успеха атомарно переключает
алиас `documents_active`. В индекс входят DOCX и PDF из папок исходных и загруженных
документов:

```sh
docker compose run --rm app python index_documents.py
```

При неудачной индексации текущая активная база остаётся доступной. Не удаляйте
коллекции `documents` и `documents_build_*` вручную во время индексации.
После успешного переключения предыдущая временная build-коллекция удаляется.

Откройте `http://10.77.0.1:8080` с устройства, подключённого к WireGuard. Проверьте список и скачивание только тестовых документов, чат, загрузку/индексацию, фильтр PII, вход администратора и перезапуск контейнеров.

## Резервное копирование и сопровождение

- Регулярно резервируйте Docker volumes `app_data` и `qdrant_data`; проверяйте восстановление копии.
- Ограничьте SSH ключами и отдельной учётной записью с `sudo`; не оставляйте парольный root-login после проверки альтернативного доступа.
- Обновляйте Ubuntu, Docker images и Python-зависимости по расписанию; фиксируйте версии и тестируйте обновления до применения.
- Ротируйте AI API key и секрет сессии при подозрении на утечку; храните `.env` только на VPS с правами `600`.
- Проверка PII основана на ограниченных шаблонах: она может ошибаться и не распознаёт все ФИО, адреса, изображения и сканы. Не полагайтесь на неё как на гарантию обезличивания.
- До расширения доступа добавьте согласованный вход сотрудников или SSO. VPN ограничивает сеть, но не разделяет права пользователей внутри неё.

## Ограничения текущего пилота

- Нет доменного имени и публичного TLS-сертификата; интерфейс доступен только через VPN. При добавлении домена настройте HTTPS и cookie `Secure`.
- Rate limit сейчас хранится в памяти процесса и подходит только для одного worker/контейнера.
- Просмотр и скачивание документов не имеют пользовательских ролей внутри VPN. Подключайте к VPN только доверенные тестовые устройства.
- Провайдер внешней модели получает запросы, проверяемые документы и фрагменты базы знаний. Используйте только синтетические данные до отдельного согласования.
- Ресурсы VPS (2 vCPU, 4 GB RAM) подходят для небольшого теста, но не являются нагрузочным или отказоустойчивым production-развёртыванием.
