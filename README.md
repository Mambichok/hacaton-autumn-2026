# Document Assistant

Небольшой внутренний помощник для работы с регламентами и типовыми документами. Это FastAPI-приложение с обычным HTML/CSS/JavaScript-интерфейсом: без отдельного frontend build шага.

## Что здесь есть

- Чат, который ищет подходящие фрагменты в документах и формирует ответ с источниками.
- Каталог документов и регламентов: PDF и DOCX.
- Каталог заполняемых DOCX-шаблонов. Администратор загружает свой DOCX и выделяет в его тексте поля; сотрудник заполняет форму и скачивает готовый файл.
- Переключение между светлой и тёмной темами с сохранением выбора в этом браузере.
- Десять стартовых шаблонов для кадровых заявлений, финансовых форм и ИТ-доступов. Приложение добавляет их при первом запуске.
- Индексация документов в Qdrant и тесты для основных функций.

## Как запустить локально

Для локальной разработки нужны Python 3.12 и Docker Engine. Версия Python важна: зависимости проекта, в частности закреплённая версия NumPy, могут не устанавливаться на более новых версиях. Docker Compose понадобится для сценария развёртывания из `DEPLOYMENT.md`.

### 1. Настроить окружение

В PowerShell из корня проекта:

```powershell
py -3.12 -m venv .venv312
.\.venv312\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
```

Откройте `.env` и задайте `OPENROUTER_API_KEY`, а также значения `SUPERADMIN_USERNAME`, `SUPERADMIN_PASSWORD` и `ADMIN_SESSION_SECRET`. Пароль супер-администратора должен быть не короче 14 символов, секрет сессии — не короче 32. Сгенерировать секрет можно так:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Не публикуйте `.env`, API-ключи и пароли в GitHub. Для локальной конфигурации оставьте `QDRANT_URL=http://localhost:6333`.

### 2. Запустить Qdrant

В отдельном окне PowerShell:

```powershell
docker run --rm --name hacaton-qdrant -p 127.0.0.1:6333:6333 -v hacaton-qdrant-data:/qdrant/storage qdrant/qdrant:v1.20.0
```

Оставьте это окно открытым, пока работает приложение. Qdrant будет доступен только с этого компьютера. Для остановки нажмите `Ctrl+C`.

### 3. Добавить документы в базу знаний

Положите утверждённые для тестирования PDF- и DOCX-файлы в `documents\original`. Затем из корня проекта выполните:

```powershell
python index_documents.py
```

Для индексации используется API эмбеддингов из OpenRouter. Без ключа или доступной модели индексация не завершится. Индекс можно безопасно пересоздавать: новая коллекция подготавливается до переключения активной базы.

### 4. Запустить приложение

```powershell
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Откройте <http://127.0.0.1:8000>. Чтобы остановить сервер, нажмите `Ctrl+C` в его окне.

## Основные настройки

Настройки читаются из `.env`; шаблон файла находится в [.env.example](./.env.example).

| Переменная | Для чего нужна |
| --- | --- |
| `OPENROUTER_API_KEY` | API-ключ для чата и эмбеддингов |
| `OPENAI_BASE_URL` | Адрес OpenAI-совместимого API; по умолчанию OpenRouter |
| `OPENAI_MODEL` | Модель ответов в чате |
| `OPENAI_EMBEDDING_MODEL` | Модель векторных представлений для поиска |
| `QDRANT_URL` | Адрес Qdrant |
| `QDRANT_COLLECTION` | Имя коллекции документов |
| `DOCUMENTS_ORIGINAL_DIR` | Каталог исходных документов |
| `DOCUMENTS_UPLOAD_DIR` | Каталог документов, загруженных через интерфейс |
| `DOCUMENT_TEMPLATES_DIR` | Каталог DOCX-шаблонов |
| `ADMIN_DATABASE_PATH` | Файл SQLite с администраторами и шаблонами |

Если переменные путей не заданы, приложение использует каталоги и файл базы данных внутри `documents`.

## Проверки

Полный набор unit-тестов:

```powershell
python -m unittest discover -v
```

Проверка синтаксиса основных Python-файлов:

```powershell
python -m py_compile app.py ask_bot.py default_templates.py index_documents.py
```

Тесты не выполняют реальные запросы к OpenRouter и не требуют переиндексации ваших документов.

## Структура проекта

```text
app.py                  FastAPI API, авторизация администратора и работа с файлами
ask_bot.py              Поиск контекста и ответы чат-бота
default_templates.py    Создание стартовых DOCX-шаблонов
index_documents.py      Чтение, разбиение и индексация документов
index.html              Разметка интерфейса
script.js               Клиентская логика
styles.css              Стили
documents/              Исходные документы, загрузки, шаблоны и SQLite
deploy/                 Файлы для закрытого тестового развёртывания
DEPLOYMENT.md            Подробная инструкция по закрытому тестовому VPS
```

## Перед использованием с реальными данными

Локальный запуск и тесты сами по себе не означают, что система готова к работе с персональными или банковскими документами. Чат и индексация используют внешний AI API; учитывайте это при выборе документов и настройке окружения. Стартовые шаблоны — универсальные заготовки, а не утверждённые формы организации. Согласуйте их и условия обработки данных с ответственными подразделениями.

Описание закрытой тестовой конфигурации, WireGuard и VPS находится в [DEPLOYMENT.md](./DEPLOYMENT.md).
